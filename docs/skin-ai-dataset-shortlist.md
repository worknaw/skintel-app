# ตัวเลือกแหล่งข้อมูลสำหรับทดลอง SkinCycle

ตรวจข้อมูลเมื่อ 3 พฤศจิกายน 2026 สถานะ: สำรวจเท่านั้น ยังไม่ได้ดาวน์โหลดภาพ ฝึกโมเดล ติดต่อเจ้าของ หรืออนุมัติใช้งานเชิงพาณิชย์

## ตัวเลือกหลัก: ภาพอาสาสมัครที่เก็บสำหรับโครงการ

ภาพเซลฟีจากอุปกรณ์และสภาพแสงที่จะใช้งานจริงตรงโจทย์ที่สุด แต่ต้องเตรียมเอกสารแสดงวัตถุประสงค์ การจัดเก็บ การลบ การส่งภาพให้ผู้ให้บริการ และการฝึกโมเดลแยกกัน ผู้เข้าร่วมต้องยินยอมตามแต่ละวัตถุประสงค์ ควรปรึกษาอาจารย์เรื่องการพิจารณาจริยธรรมวิจัยก่อนเก็บจริง จัดผู้ประเมินและ label ตาม `skin-ai-evaluation-protocol.md`

## ACNE04: ชุดข้อมูลวิจัยเรื่องสิว

ผู้สร้างเผยแพร่ใน [repository ของงานวิจัย](https://github.com/xpwu95/LDL) และระบุว่าใช้เพื่อการศึกษาได้ ส่วนการใช้วัตถุประสงค์อื่นให้ติดต่อผู้สร้าง ต้องตรวจเงื่อนไขภาพ การประมวลผลผ่าน provider และการเผยแพร่โมเดลเพิ่มเติมก่อนใช้ งานวิจัยระบุว่าชุดข้อมูลมีภาพและ label สิว แต่ภาพบางส่วนมีคุณภาพต่ำ ([บทความ](https://numbda.cs.tsinghua.edu.cn/papers/thc22.pdf))

ข้อจำกัด: label ระดับความรุนแรงและภาพที่มีในชุดไม่เท่ากับ label แบบ `observed`/`not_observed`/`unassessable` ของโครงการ และยังไม่ยืนยันว่ามีผู้ไม่เป็นสิวหรือข้อมูลบ่งชี้บุคคลพอสำหรับแยกข้อมูลตามคน ไม่ใช้ตัดสินประสิทธิภาพบนภาพเซลฟีของผู้ใช้โดยลำพัง ห้ามแปลงระดับสิวเป็น label อื่นโดยไม่กำหนดวิธีและตรวจสอบก่อน

การสำรวจเพิ่มเติม 4 พฤศจิกายน 2026: [ชุดที่นำมาจัดรูปแบบใหม่บน Hugging Face](https://huggingface.co/datasets/Layered-Labs/ACNE04) ระบุภาพ 1,457 ภาพ ขนาดรวมประมาณ 1.13 GB พร้อม label สิว 4 ระดับซึ่งเริ่มจาก mild ไม่ใช่กลุ่มที่ยืนยันว่าไม่มีสิว ในรายการ fields ที่แสดงไม่พบ patient ID จึงยังยืนยันการแยกชุดตามบุคคลไม่ได้ ผู้จัดชุดระบุว่าบาง test folds ซ้อนทับกัน และไม่ได้กล่าวว่ามี label สำหรับรอยแดง ชุดนี้จึงเหมาะเริ่มศึกษาภาพและ label สิวสำหรับงานวิชาการ แต่ยังใช้วัด false positive, สร้าง threshold ที่ใช้ทั่วไป หรืออ้างความแม่นยำสำหรับเซลฟีผู้ใช้จริงไม่ได้ หากใช้ต้องอ้างอิงทั้งงานต้นฉบับและผู้จัดชุดตามเงื่อนไขและตรวจสิทธิ์ทุกขั้นตอน

## DDI และ Fitzpatrick17k: เอกสารอ้างอิงด้านความหลากหลาย

- [Stanford DDI](https://aimi.stanford.edu/datasets/ddi-diverse-dermatology-images) เป็นภาพโรคผิวจากคลินิกหลายสีผิว ไม่ใช่ชุดภาพเซลฟีสำหรับโจทย์นี้ ตรวจข้อตกลงการเข้าถึงก่อนใช้
- [Fitzpatrick17k](https://github.com/mattgroh/fitzpatrick17k) ระบุ CC BY-NC-SA 3.0 และภาพมาจากแหล่งต้นฉบับต่างกัน ต้องตรวจสิทธิ์ของภาพและการส่งต่อแยกอีกครั้ง ภาพโรคผิวไม่ได้เป็นชุดทดสอบเซลฟีที่ตรงโจทย์

ทั้งสองชุดเหมาะศึกษาอคติและแนวทางออกแบบการประเมิน แต่ไม่ถือว่าเป็นหลักฐานว่าระบบ SkinCycle ใช้ได้กับทุกสีผิว

## การเลือกโมเดลและ benchmark

1. เริ่มจาก baseline แบบ `unassessable` ทุกภาพเพื่อตรวจว่า evaluation แยกการไม่ตอบออกจากการทำนายได้ และเปรียบเทียบ Vision model ที่เลือกโดยใช้ชุดเดียวกัน
2. เลือก provider หลังตรวจราคา ความเป็นส่วนตัว การเก็บ/ใช้ข้อมูล และการส่งต่อภาพให้สอดคล้องกับ consent; การเข้าถึง provider และงบประมาณยังไม่ได้กำหนด
3. โมดูล `src/features/skin-analysis/evaluation/benchmark.ts` สรุป confusion matrix และ precision/recall พร้อมนับการงดประเมิน ไม่เชื่อมภาพหรือ provider ไม่อ้างความน่าเชื่อถือจากตัวเลขจำลอง
4. ก่อนสรุปผลจริง ต้องคำนวณช่วงความไม่แน่นอนโดยคำนึงถึงหลายภาพต่อคนและประเมินแยกตามกลุ่มตาม protocol; โมดูลปัจจุบันยังไม่ทำ bootstrap หรือ subgroup analysis

ก่อน benchmark จริงต้องมีภาพที่ได้รับสิทธิ์ label อิสระ ข้อมูลแบ่งตามบุคคล และ provider ที่ได้รับเลือก ระบบนี้ยังไม่พร้อมวัดความแม่นยำหรือให้คำแนะนำผู้ใช้

## แนวทางโมเดลที่ควรทดลอง

- Baseline `unassessable` ทุกภาพใช้ตรวจระบบประเมิน ไม่ใช่โมเดลทำนาย
- [SigLIP 2 base](https://huggingface.co/google/siglip2-base-patch16-224) เป็นโมเดลภาพทั่วไปที่ระบุ Apache-2.0 และทดลองในเครื่องได้ แต่ไม่ได้ผ่านการรับรองสำหรับประเมินผิว ความสามารถตรวจสิวหรือรอยแดงยังไม่ทราบ ต้องวัดบนข้อมูลที่ตรงโจทย์และปรับ threshold จาก validation เท่านั้น
- โมเดล vision แบบบริการเป็นตัวเปรียบเทียบเมื่อเลือก provider แล้ว ต้องตรวจสิทธิ์การส่งภาพ ค่าใช้จ่าย ระยะเวลาเก็บและนโยบายข้อมูลของบัญชีจริงก่อนส่ง ตัวอย่าง [เงื่อนไข Gemini API](https://ai.google.dev/gemini-api/terms) แตกต่างระหว่างบริการแบบเสียเงินและไม่เสียเงิน ห้ามสมมติว่าทุกแผนมีนโยบายเดียวกัน

## ใช้เครื่องมือ benchmark

ต้องใช้ Node.js 24 หรือรุ่นที่รองรับการรัน TypeScript แบบ type stripping เครื่องมือนี้อ่านเฉพาะ JSON ที่เตรียมไว้ในเครื่อง ไม่อ่านรูปและไม่เรียกเครือข่าย ใช้รหัสสุ่มแทนข้อมูลระบุตัวตน เก็บไฟล์ข้อมูลจริงนอก Git และไม่ใส่รูปหรือข้อมูลส่วนบุคคลใน output

```sh
node scripts/skin-ai-benchmark.mjs <path-to-local-input.json>
```

ตรวจว่าเครื่องมือทำงานได้ด้วยข้อมูลสมมติที่ไม่มีภาพหรือผลโมเดลจริง:

```sh
node scripts/skin-ai-benchmark.mjs src/features/skin-analysis/evaluation/fixtures/synthetic-input.json
```

โฟลเดอร์ `skin-ai-data/` ถูกตั้งค่าให้ Git ข้ามไฟล์ แต่ไม่ใช่ระบบเข้ารหัสหรือระบบควบคุมสิทธิ์ ต้องจัดเก็บและควบคุมการเข้าถึงข้อมูลจริงตามเงื่อนไขการยินยอม

Input ประกอบด้วย `datasetVersion`, `split` (`validation` หรือ `test`), `modelVersion` และ `records` ซึ่งแต่ละรายการมี `participantId`, `imageId`, `finding`, `reference`, `predicted` ค่าของ `finding` คือ `visible_acne` หรือ `visible_redness` ส่วน `reference` และ `predicted` คือ `observed`, `not_observed` หรือ `unassessable` ต้องมีผลอิสระจากผู้ประเมินก่อน

ผลเป็น JSON บนหน้าจอ มีตารางความสับสนและจำนวนที่งดประเมิน แยก recall เมื่อดูเฉพาะคำตอบกับ recall ที่นับการงดประเมิน; ค่า null หมายถึงคำนวณไม่ได้เพราะไม่มีข้อมูลพอ เมื่อต้องเทียบโมเดลต้องตรวจด้วยตนเองว่าใช้ dataset/split และรายการภาพเดียวกัน โดยเครื่องมือนี้ยังไม่ตรวจการรั่วข้าม train/validation/test ไม่คำนวณช่วงความไม่แน่นอน และไม่ตัดสินว่าโมเดลพร้อมใช้งาน
