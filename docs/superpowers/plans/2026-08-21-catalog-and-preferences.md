# Catalog and User Preferences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve existing product screens from seeded Supabase data and persist the existing user notification/privacy toggle state without changing UI.

**Architecture:** Public catalogue rows live in RLS-protected tables that only expose `SELECT` to client roles. A feature-local Supabase repository maps these rows to the existing product domain types. Owner-only user settings are persisted separately and use optimistic updates with rollback.

**Tech Stack:** Expo SDK 57, TypeScript, React Query, Supabase Postgres/RLS, Supabase JS, Jest.

**Spec:** `docs/superpowers/specs/2026-08-21-catalog-and-preferences-design.md`

## Global Constraints

- Do not change any visible UI layout, spacing, size, font, color, border, radius, shadow, icon, image, animation, wording, element position, or navigation-bar appearance.
- Use only `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in the Expo client.
- Every `public` table has explicit grants and RLS enabled.
- Catalogue data is read-only from mobile clients.
- `user_settings` is visible and mutable only to its authenticated owner.
- AI/image processing remains excluded; privacy toggles only store preferences.
- Generate a new local migration through `npx supabase migration new <name>` before applying the final verified SQL with Supabase MCP.

- [x] **Step 2: Apply schema constraints and client grants**

```sql
create table public.user_settings (
  user_id uuid primary key references auth.users(id) on delete cascade,
  routine_morning boolean not null default false,
  routine_evening boolean not null default false,
  skin_cycling boolean not null default false,
  reanalysis_reminder boolean not null default false,
  promotions boolean not null default false,
  image_analysis boolean not null default false,
  recommendation_personalization boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
grant select, insert, update on public.user_settings to authenticated;
alter table public.user_settings enable row level security;
create policy "user_settings_select_own" on public.user_settings for select to authenticated using ((select auth.uid()) = user_id);
create policy "user_settings_insert_own" on public.user_settings for insert to authenticated with check ((select auth.uid()) = user_id);
create policy "user_settings_update_own" on public.user_settings for update to authenticated using ((select auth.uid()) = user_id) with check ((select auth.uid()) = user_id);
```
