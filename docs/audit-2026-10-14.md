# Full Project Audit — SkinCycle

วันที่ตรวจ: 14 ตุลาคม 2026 (Asia/Bangkok)

## 1. Project Health Summary

ตรวจ configuration, route/screen ที่ใช้งาน, auth/session, repositories, settings forms, Supabase migrations, timers/listeners, dependency graph, assets และ tests ของโปรเจกต์จริงก่อนแก้ไข เป็นการแก้แบบ incremental โดยรักษา UI ที่ใช้งาน ไม่มีการเปลี่ยน layout, สี, ขนาด, ฟอนต์, icon, รูปภาพ หรือ animation

โครงสร้าง: Expo SDK 57 / React Native 0.86.2 / React 19.2.3 / TypeScript 6, Expo Router root native Stack + JavaScript bottom Tabs, React Query สำหรับ server state, Supabase Auth และ Data API ผ่าน publishable key, SecureStore สำหรับ session บน native และ AsyncStorage บน browser

Graph scan ตรวจ source modules 75 ไฟล์ ไม่พบ circular import ใน graph ที่ resolve ได้จาก literal imports (ไม่ใช่การพิสูจน์ runtime ทุกกรณี) โค้ดแบ่งตาม feature แต่บาง screen ยังเรียก Supabase โดยตรง และ settings ยังอยู่ใน route file เอกสาร architecture บางส่วนเป็นเป้าหมายในอนาคต ไม่ใช่ระบบที่ implement ครบแล้ว

สถานะ: build และ tests ผ่านหลังแก้ bug ที่ยืนยันได้ แอปยังไม่พร้อมประกาศ Production-ready เพราะ backend settings บางส่วนยังไม่ปรากฏใน Data API, หลาย feature ยังเป็น demo/placeholder, และยังไม่ได้ทดสอบ authenticated flows/RLS ระหว่างสองบัญชีครบ

Git เริ่มต้นแสดงไฟล์โปรเจกต์เป็น untracked จึงไม่มี commit baseline สำหรับ diff ทั้งโปรเจกต์ เก็บงานเดิมไว้ ไม่ reset, checkout หรือสร้าง commit แทนผู้ใช้

## 3. Changes Implemented

- `src/core/supabase/client.ts`: แยก storage/session behavior ของ SSR ออกจาก browser/native แก้ web export crash
- `src/app/settings.tsx`: synchronous mutation locks, loading readiness, per-field merge, owner/unmount guards ลด state race โดยไม่เปลี่ยน style
- `src/features/settings/ui/settings-detail-screen.tsx`: ป้องกัน auth redirect แข่งระหว่างลบบัญชี
- `src/features/auth/ui/auth-session-provider.tsx`: native AppState token refresh lifecycle และ cleanup
- `src/features/auth/ui/auth-screen.tsx`: stronger email validation, lifecycle-aware async feedback, ป้องกันปิดหน้าในช่วง submit
- `src/features/auth/application/oauth-callback.ts`: handle malformed callback โดยไม่ throw
- `src/hooks/use-debounced-value.ts` และ Discover: debounce, timer cleanup, route intent synchronization ที่รักษา draft เมื่อสลับแท็บธรรมดา
- Home: navigate ไป Discover พร้อม filter intent และล้าง params ที่ไม่เกี่ยวข้อง
- Product repository/interface/query options: optional cancellation signal, correct popular/recent ordering, finite page sizes, literal search escaping และวางสินค้าที่ไม่มีราคาไว้ท้าย price sort
- Scan reducer/screen: interval ต่อ stage, stage validation และ progress monotonicity; animation เดิมคงอยู่
- Product detail: HTTPS link guard และ back fallback สำหรับ direct entry
- Profile/scan: ลบ unused `headerButton` / `uploadButton` style declarations ที่ไม่มี references แล้ว
- `package-lock.json`: update shell-quote หนึ่ง transitive dependency; package.json direct dependencies ไม่เปลี่ยน
- `scripts/audit-project.cjs`: read-only source graph/asset inventory สำหรับตรวจซ้ำ ไม่มี automatic deletion
- Tests: เพิ่ม regression สำหรับ concurrent settings, debounce/cleanup, stale auth restore, malformed callback, query normalization และ stale scan events

## 6. Further Recommendations

### จำเป็นก่อน Production

1. ให้สิทธิ์ตรวจโปรเจกต์ Supabase ที่ถูกต้อง ตรวจ migration settings และ schema/RLS จริง แล้วทดสอบ insert/update/export/delete ด้วยบัญชีทดสอบและ user A/B อย่าทดสอบ destructive operations ด้วยบัญชีผู้ใช้จริง
2. ทำรอบ SDK57 patch update ที่ระบุจาก expo install --check โดยดู changelog โดยเฉพาะ RN0.86.3/Router57.0.26 แล้ว native rebuild และ replay navigation/auth regression ไม่ใช้ npm audit fix --force ที่แนะนำการ downgrade/major upgrade ข้าม SDK
3. สร้าง release/internal test build วัด transition frame times, cold start, PSS/RSS หลัง warm-up และ navigation soak แบบเดียวกัน หาก view/heap โตต่อให้จับ heap/native trace ก่อนเปลี่ยน navigator หรือ animation
4. ทำ recovery/deep-link/new-old user/login/logout/session-expiration flows ให้ครบ และ review consent/retention/deletion/nโยบายให้ตรงระบบจริง
5. เชื่อม favorites, history, routine persistence และ interaction ที่ยังเป็น placeholder ตาม priority; AI ทำในงานถัดไปตามขอบเขตเดิม

### ทางเลือกที่มีประโยชน์

- CI typecheck/lint/test/Expo export พร้อม regression gates และ dependency advisory triage
- เพิ่ม database types/generated contracts และ runtime validation ที่ boundary เมื่อขยาย schema
- แยก template components ที่ไม่ใช้ไป archive เมื่อยืนยันว่าไม่ใช่แผน feature พร้อมรักษา domain/service interfaces ที่ยังต้องใช้
- พิจารณา lossless asset optimization และ cache strategy หลังเก็บ release metrics โดยเทียบภาพก่อน/หลัง
