# คู่มือทดลองประเมินภาพผิว รุ่น 0.1

เอกสารนี้ใช้เตรียม benchmark ภายใน ยังไม่ยืนยันความแม่นยำหรืออนุญาตให้นำผลไปใช้กับผู้ใช้จริง

## สิทธิ์และการเตรียมชุดภาพ

- รับเฉพาะภาพที่เจ้าของยินยอมตามวัตถุประสงค์และมีสิทธิ์ใช้ทดลอง รวมถึงข้อกำหนดการส่งต่อให้ผู้ให้บริการ AI แยกจากสิทธิ์ฝึกโมเดล
- เก็บทะเบียนแหล่งภาพ ข้อกำหนด license วิธีขอถอนความยินยอม และวันลบ; ห้ามนำภาพที่สิทธิ์ไม่ชัดเจนมาใช้
- กำหนด participant ID แบบสุ่มและ image ID ไม่ใช้ชื่อหรืออีเมลเป็นชื่อไฟล์; จำกัดผู้เข้าถึงและรักษาไฟล์ mapping แยกต่างหาก
- ระบุอุปกรณ์ สภาพแสง ภาพด้านหน้า/ด้านข้าง และการแต่งหน้าหรือฟิลเตอร์เท่าที่จำเป็นและได้รับอนุญาต
- แบ่งข้อมูลตาม participant ID ก่อนปรับโมเดลหรือทดลอง prompt; เก็บ test แยกและไม่ใช้เลือก prompt หรือ threshold

## การประเมินคุณภาพภาพ

ผู้ประเมินบันทึก `usable`, `unusable` หรือ `uncertain` พร้อมเหตุผล เช่น ไม่มีใบหน้าชัดเจน หลายใบหน้า ภาพเบลอ แสงไม่พอ แสงจ้าจนรายละเอียดหาย สิ่งบังหรือฟิลเตอร์รบกวน และระบุว่ามองเห็นบริเวณใดได้ หากไม่แน่ใจให้ระบุ `uncertain` ไม่อนุมานข้อมูลที่มองไม่เห็น

## เกณฑ์ label ของภาพ

ผู้ประเมินอย่างน้อยสองคนให้ label แยกกันโดยไม่เห็นผล AI หรือ label ของอีกคน:

| รายการ | observed | not_observed | unassessable |
| --- | --- | --- | --- |
| `visible_acne` | เห็นลักษณะที่ผู้ประเมินระบุว่าอาจเป็นสิวในบริเวณที่เห็น | ไม่เห็นลักษณะดังกล่าวในบริเวณที่ตรวจได้ | ภาพหรือบริเวณที่เห็นไม่พอให้ประเมิน |
| `visible_redness` | เห็นบริเวณแดงเมื่อเทียบกับผิวใกล้เคียง โดยแสงไม่รบกวนจนแยกไม่ได้ | ไม่เห็นบริเวณแดงในบริเวณที่ตรวจได้ | แสง สีภาพ สีผิว หรือคุณภาพไม่เอื้อต่อการประเมิน |

`not_observed` ไม่หมายถึงไม่มีสิวหรือรอยแดงทั้งใบหน้า ให้บันทึกบริเวณที่ตรวจได้และเหตุผลที่ประเมินไม่ได้ ห้ามให้คะแนนความชุ่มชื้น ประเภทผิว โรค หรือความรุนแรงทางคลินิกจาก label ชุดนี้

จัด calibration session ด้วยภาพตัวอย่างที่มีสิทธิ์ใช้ แล้วปรับคู่มือเมื่อพบความกำกวม บันทึก version คู่มือและความเห็นที่ไม่ตรงกันไว้ ให้ผู้เชี่ยวชาญทบทวนกรณีขัดแย้งโดยไม่ลบ label ดั้งเดิม

## วิธีเปรียบเทียบ

1. บันทึก dataset version, วันที่ freeze และการแบ่งชุดตามบุคคล
2. ให้ baseline และ model ที่ทดลองประเมินภาพ test เดียวกันด้วย prompt/config เดียวกันในแต่ละรุ่น โดยผู้ให้ label ไม่เห็นผลโมเดล
3. รายงานจำนวนคนและภาพต่อกลุ่ม ตารางสับสนสำหรับแต่ละ label, precision/recall/F1 และช่วงความไม่แน่นอนที่คำนวณโดยคำนึงถึงการมีหลายภาพต่อคน
4. รายงานอัตรา `unassessable` และสัดส่วนกรณีที่โมเดลบอก `not_observed` แต่ผู้ประเมินเห็นลักษณะดังกล่าว รวมทั้งคุณภาพภาพที่ถูกปฏิเสธผิด
5. แยกผลตามกลุ่มสีผิว สภาพแสง และอุปกรณ์เมื่อจำนวนข้อมูลพอ ระบุตัวอย่างต่อกลุ่มและความไม่แน่นอน หลีกเลี่ยงการอ้างว่าผ่าน fairness จากกลุ่มที่เล็ก
6. ทดสอบความสม่ำเสมอเมื่อถ่ายซ้ำ และตรวจผลที่ไม่ปลอดภัย เช่น อ้างโรค แนะนำยา หรือให้คะแนนที่ไม่มีข้อมูลรองรับ
7. เกณฑ์รับผลและขนาดตัวอย่างต้องกำหนดร่วมกับผู้ประเมินก่อนเปิด test โดยอิงวัตถุประสงค์และข้อจำกัดของโครงการ

## บันทึกผลต่อหนึ่งภาพ

บันทึกเฉพาะ `participant_id`, `image_id`, `dataset_version`, คุณภาพภาพ/บริเวณที่ตรวจได้, label และเหตุผลจากผู้ประเมินแต่ละคน, label ที่ตกลง, model/prompt version, output ที่ผ่าน schema และสถานะการยินยอม ไม่ส่งชื่อ อีเมล หรือภาพไปยัง log รายงานผลภาพรวม และเก็บภาพเฉพาะเท่าที่ได้รับสิทธิ์
